会议纪要助手 0.5.2 使用说明

会议纪要助手是一个本地运行的飞书会议助手。它接收飞书中的会议录音或转录文字， 在本机完成转写、说话人分离、纪要生成和文件导出，再把正式纪要回传到飞书；纪要生成可使用 Codex CLI、OpenAI 兼容 API、Anthropic、LM Studio 或 Ollama。

核心能力

  • 接收飞书录音文件或已转录文字材料。
  • 完成音频转换、说话人分离、语音转写和纪要生成；分离与转写均显示实时进度。
  • Apple Silicon 上说话人分离优先使用 Apple GPU；语音转写默认启用 16 线程与批量处理。
  • 纪要生成默认使用 Codex CLI，也可切换到 OpenAI 兼容 API、Anthropic、LM Studio 或 Ollama。
  • 支持重复材料复用，避免重复转写。
  • 支持引用历史音频重新生成纪要，或强制重新转录。
  • 支持会后补充说话人姓名，并同步更新实名转录稿、会议纪要及导出文件。
  • 默认不在聊天中展开完整转录稿，只发送摘要和正式文件。
  • 支持在本地会议库中选择或拖入材料；提交后立即建立临时会议条目，关闭新增窗口后主界面底部继续显示进度并可暂停。
  • 本地新增会议按阶段保存检查点；暂停、崩溃或 App 重开后可复用已有材料继续，转录完成后也可单独重试生成纪要。
  • 同一时刻只允许运行一个本地新增会议任务，避免重复任务争抢资源。
  • 支持在会议详情页直接切换中文纪要类型，并在确认后重新生成文件。
  • 支持一次新增多个标签，并在详情页统一保存或撤销修改。
  • 会议详情页和概览页最近一次会议的 HTML、DOCX、MD、PDF 文件按钮在对应文件缺失时，可右键补生成该文件，生成后会切换为可打开状态。
  • 主窗口底部状态栏会显示会议统计；本地会议处理时同步显示阶段、百分比和中止按钮。
  • 会议详情标题、保存和撤销操作固定在右侧顶部，不随正文滚动。

处理工作流与说话人显示

  1. 将录音转换为 16 kHz 单声道 WAV。
  2. 执行说话人分离，判断谁在什么时间说话；Apple Silicon 默认优先使用 MPS GPU。
  3. 执行语音转写，识别具体内容，并显示百分比与已处理时长。
  4. 对齐说话人与文字，生成转录稿、会议纪要和导出文件。
  • 内部 SPEAKER_00、SPEAKER_01 显示为“说话人1”“说话人2”。
  • UNKNOWN 统一显示为“未知说话人”。
  • 标注真实姓名并保存后，会议库、转录稿和会议纪要同步显示真实姓名。

转写性能配置

ASR_MODEL=medium
ASR_LANGUAGE=zh
ASR_CPU_THREADS=16
ASR_BATCH_SIZE=8
ASR_BEAM_SIZE=5

默认配置保持 medium 模型和 beam size 5，并通过 CPU 线程和批量转写提速。减小模型或 beam size 可进一步加速，但可能降低中文准确率。

纪要生成后端

LLM_PROVIDER=codex
LLM_API_BASE=
LLM_API_KEY=
LLM_MODEL=
LLM_TIMEOUT_SECONDS=600
LLM_MAX_ATTEMPTS=3

默认后端是 Codex CLI；如需使用其他服务，可在设置页或 .env 中切换到 OpenAI 兼容 API、Anthropic、LM Studio 或 Ollama。

典型使用方式

  1. 向飞书机器人发送录音文件，或直接上传转录文本。
  2. 机器人在本机处理后，把正式纪要文件回传到飞书。
  3. 如需复用历史音频，可引用原消息并发送“重新生成会议纪要”。
  4. 如需强制重跑语音识别，可引用音频并发送“重新转录”。
  5. 如需补充说话人姓名，可发送 说话人1=张老师。
本软件默认把录音缓存保存在 ~/Library/Application Support/meeting-bot/downloads/， 把会议音频副本、转录稿和纪要保存在 ~/Library/Application Support/meeting-bot/sessions/； 这两个目录都可在设置中修改。飞书 App Secret、Hugging Face Token 等敏感配置只应写入本机 .env。
