# 会议纪要助手 0.7 封版计划

更新时间：2026-07-31

## 状态

`0.7.2 build 38` 是当前封版候选版，但 0.7 尚未完成正式封版。只有本文列出的验证、安装升级、真实任务和发布步骤全部通过后，才能把对应版本标记为最终 0.7 Release。

封版后，0.7 进入维护状态：不再新增功能，不再继续原计划中的 0.8、0.9 Python 技术路线；只接受严重安全问题、数据损坏、无法启动和无法迁移问题的修复。

## 版本规则

- 若封版不产生代码或发布内容修改，可沿用已经验证的版本元数据。
- 本轮封版诊断修补已推进到 `0.7.2`、build `38`。
- 后续每一批确认完成的修补按 `0.0.1` 和 build `+1` 推进。
- 最终版本号以封版测试完成后的实际修改批次为准，不在测试前预写。

## 封版范围

### 1. 代码与数据基线

- 固定当前 Python 后台、Swift App、安装升级脚本、数据恢复工具和任务账本。
- 确认本地导入与飞书任务继续使用同一任务 ID、状态机和检查点。
- 构造损坏元数据、重复事件、中断任务和重试任务，确认不会覆盖原始资料或重复生成正式会议。
- 检查仓库、安装盘和诊断包不包含 `.env`、Token、会议正文、录音或用户目录。

### 2. 自动化与真实任务验证

- 全量 Python 测试通过，测试数量和结果写入交接文档。
- Python 编译检查和 Shell 语法检查通过。
- Swift App 无警告构建，载荷清单验证和 `codesign --verify --deep --strict` 通过。
- 使用代表性录音完成一条本地任务：导入、转写、说话人分离、对齐、纪要、导出、实名修改和重新导出。
- 使用代表性文本完成一条跳过 ASR 的任务。
- 验证暂停、继续、中止、失败重试、App 重开和重复提交。
- 验证飞书真实消息、引用历史材料、重新转录、重新生成纪要和说话人命名。

### 3. 安装、升级与恢复

- 覆盖全新安装、0.6 升级、现有 0.7 覆盖安装、网络中断、磁盘不足和权限不足。
- 验证非 Homebrew 安装的 Python、Codex CLI、LibreOffice 和其他受支持工具能被正确识别。
- 安装失败后恢复旧 App、后台组件和环境，会议资料保持不变。
- 发布包的版本、build、清单、哈希、签名状态和文档一致。
- 正式公开分发前完成 Developer ID 签名、Apple 公证、stapling 和 Gatekeeper 验证。

### 4. 卸载器收口

卸载器必须采用应用所有权白名单，不得把用户设置的录音目录或纪要目录整体视为应用数据。

- 默认删除 App、LaunchAgent、应用自有后台载荷、虚拟环境、缓存和日志。
- 默认保留会议库、录音、转录稿、纪要、导出文件、备份和配置。
- 删除用户资料必须是独立选项，执行前列出精确目录、预计大小和文件类别，并二次确认。
- 自定义目录只删除能够证明由本应用创建的文件；不能证明所有权时失败关闭。
- 不删除 `/Users/Peng/Developer/meeting-bot-1.0-native`、1.0 Preview、1.0 数据容器或其模型。
- 写入不含会议正文和密钥的卸载结果日志，失败时保留可恢复信息。

当前验证：卸载器编译、代码签名检查、无副作用扫描和临时目录自检已通过。实际扫描没有把源码仓库或 `/Users/Peng/Developer/meeting-bot-1.0-native` 纳入删除目标；内部测试安装盘已确认同时包含主 App 和卸载器。

安装事务已在隔离目录模拟“部署运行组件后失败”：安装器返回测试退出码 `97`，旧运行组件自动恢复，`.env`、会议资料和无关文件逐项比对保持不变。该演练不替代真实机器上的全新安装、覆盖升级、网络中断、磁盘不足和权限不足验证。

本机工程验证、合成文本/双说话人音频真实流水线、虚构实名同步和飞书官方鉴权结果已记录于`docs/RELEASE_0.7_VERIFICATION.md`。当前仍缺 Developer ID、公证、真实飞书消息、完整安装矩阵和最终 GitHub Release，因此本计划状态保持“未正式封版”。

### 5. 文档与发布

- 同步 README、安装、升级、卸载、使用、依赖、隐私、线程交接和开发路线图。
- 明确 0.7 是最后一个 Python 架构版本，并说明 1.0 采用独立原生工作区。
- 提交封版变更，合并到 `main`，创建最终 0.7 标签和 GitHub Release。
- Release 附带安装盘、SHA-256、发布清单、测试摘要、许可证和已知限制。
- 建立 0.7 维护分支；1.0 不从维护分支持续吸收功能，只挑选必要缺陷修复。

## 封版完成定义

只有同时满足以下条件，才可在文档中写“0.7 已封版”：

- 封版范围内的自动化测试、真实任务、安装升级和卸载验证全部通过。
- 没有未处理的高严重性安全或数据完整性问题。
- 最终 App、安装盘、版本、build、发布清单和文档一致。
- GitHub 上存在不可变版本标签和对应 Release。
- 0.7 维护边界和 1.0 迁移入口已经写入交接文档。
