## ① 安装/升级时无法准确定位满足要求或历史使用过的 Python、依赖库

### 根因

- Swift 侧 `BootstrapInstaller.swift` 只会在用户手动点击「选择已有 Python」后，
  通过 `chooseExistingPython()` 校验**单个**手选路径，不会主动扫描机器上已存在的解释器。
- 真正的环境探测在 `scripts/install.sh`（`--dependency-mode auto` 分支）。当前 `auto`
  的"复用现有环境"只检查项目目录下的 `.venv`，没有扫描系统常见 Python 安装位置，
  也没有复用历史安装目录（`~/meetin-bot`、`~/meeting-bot`、`~/feishu-meeting-bot`）里
  遗留的可用 `.venv`。
- 依赖库（wheelhouse / pip 缓存）同理：`auto` 优先用 `wheelhouse/`，但不会探测
  历史安装目录中已下载好的 wheel。

### 改动方案（`scripts/install.sh`）

1. 新增 `detect_python()`：按优先级扫描并校验版本 ≥ 3.12，命中即用：
   - 本次安装目标目录的 `.venv/bin/python`；
   - 历史安装目录 `~/meetin-bot`、`~/meeting-bot`、`~/feishu-meeting-bot` 下的
     `.venv/bin/python`；
   - `pyenv` 版本目录（`~/.pyenv/versions/*/bin/python3`）；
   - Homebrew（`/opt/homebrew/bin/python3.12+`、`/usr/local/bin`）；
   - `/Library/Frameworks/Python.framework/Versions/*/bin/python3`；
   - `command -v python3` 的 PATH 结果。
   每个候选都执行 `python -c 'import sys; print(sys.version_info[:2])'` 校验，
   把第一个 ≥ 3.12 的作为 `PYTHON_BIN`。
2. `--python-bin` 显式传入时跳过扫描，但仍做版本校验。
3. 依赖复用：若历史 `.venv` 可用且 `pip check` 通过，则直接 `clone`/复用，
   不重复联网安装；否则按 `wheelhouse/` → 在线 的顺序回退。
4. 把每一步探测结果打印成中文行（例如 `已复用历史 Python: /Users/.../.venv/bin/python`），
   便于 Swift 安装窗口实时显示。

### Swift 侧已具备的对接点（无需再改）

- `BootstrapInstaller.swift` 已能传 `--python-bin` 和 `--dependency-mode`，
  并已通过 `isPythonIssueLine()` 识别 Python 相关输出行。
- 若希望「自动探测到的历史 Python」也展示给用户确认，可在 install.sh 输出
  形如 `检测到可复用 Python: <path>` 的行，再在 `appendOutput` 中解析（小改动，
  届时一并处理）。

## ⑥ 新增会议时界面应显示详细的执行进度

### 根因

- `MeetingLibraryStore.createLocalMeeting()` 调用 `scripts/create_local_meeting.py`，
  但只在进程**结束后**一次性读取 stdout，过程中界面只显示一个转圈 +「正在处理」。
- `create_local_meeting.py` 目前（推测）仅在结束时打印一行 JSON 结果，
  没有逐阶段输出。

### 改动方案

**Python 侧（`scripts/create_local_meeting.py`）**

按阶段把进度写到 stdout，每行一个 JSON，例如：

```
{"stage": "importing_audio", "message": "正在导入录音"}
{"stage": "converting_audio", "message": "正在转换音频"}
{"stage": "diarization", "message": "正在进行说话人分离"}
{"stage": "transcribing", "message": "正在语音转写"}
{"stage": "classifying_meeting", "message": "正在识别会议类型"}
{"stage": "generating_report", "message": "正在生成会议纪要"}
{"stage": "generating_exports", "message": "正在导出 HTML/DOCX/PDF"}
{"session_id": "<最终结果>"}   # 最后一行仍是结果 JSON
```

阶段名建议直接复用 Swift 侧 `Models.swift` 的 `StageDisplay`（`received_audio`、
`converting_audio`、`diarization`、`transcribing`、`classifying_meeting`、
`generating_report`、`generating_pdf` 等），这样无需新增中文映射。

**Swift 侧（`MeetingLibraryStore.createLocalMeeting`）**

- 改为像 `BootstrapInstaller.start()` 那样，给 stdout 的 `Pipe` 设置
  `readabilityHandler`，按行增量解析。
- 新增 `@Published private(set) var localMeetingStage: String = ""`，
  每收到一行 `{"stage": ...}` 就用 `StageDisplay.name(for:)` 更新。
- 最后一行（含 `session_id`）仍走现有的 `decodeLocalMeetingCreationResult`。
- `NewMeetingWindowView`（`MainWindowView.swift:1701` 附近）把
  「正在处理」替换为 `store.localMeetingStage`，并可加一个
  `ProgressView(value:)` 按阶段序号显示百分比。

> 该项属"Swift + Python 都要改"，Swift 侧改动不大，但依赖 Python 先产出
> 分阶段输出，因此整体归入后台待办。

---

### 实现情况（0.2.9）

- `scripts/create_local_meeting.py` 新增 `emit_progress`，并在 `write_runtime_status`
  每个阶段向 stdout 输出 `{"progress": {"stage": ..., "message": ...}}` 行，
  额外补充 `generating_report_exports` 导出阶段。
- `MeetingLibraryStore.createLocalMeeting` 改为流式读取 stdout/stderr，逐行解析
  progress 并实时刷新 `localMeetingCreationMessage`；新增会议窗口随之显示阶段进度。

## ⑦ 重新选择会议模板生成纪要时，无法指定说话人真实姓名

### 根因

- `MeetingLibraryStore.regenerateReport(for:templateID:)` 只向
  `scripts/regenerate_session.py` 传 `--session` 和 `--template`，
  **没有传说话人映射**。
- 用户在「说话人标注」里填的真实姓名保存在
  `library/meeting_library.json` 的 `sessions[sessionID].speakerLabels`
  （`SPEAKER_00 → 张三`），重生成时未被使用，结果仍是匿名版。

### 改动方案

**Swift 侧（`MeetingLibraryStore.regenerateReport`）**

- 在拼参数时附带当前会议的说话人映射。两种方式任选：
  - 直接传 JSON 字符串：`--speaker-map '{"SPEAKER_00":"张三"}'`；
  - 或写入临时文件后传路径：`--speaker-map-file /tmp/xxx.json`（推荐，避免命令行转义问题）。
  数据来源：`metadata.sessions[meeting.sessionID]?.speakerLabels`。
- 建议把重生成入口改为「先确认说话人姓名」：在
  `MainWindowView.swift` 的 `pendingMeetingTypeChange` 确认弹窗里，
  若该会议存在 `detectedSpeakers` 且尚未全部标注，先引导用户填写姓名再生成。

**Python 侧（`scripts/regenerate_session.py`）**

- 接收 `--speaker-map` / `--speaker-map-file`，把 `SPEAKER_xx` 替换为真实姓名后
  再做分类与纪要生成；输出版本标记为 `named`（实名版），写入对应的
  `report_named.json` / `transcript_named.md`。
- 若未提供映射，保持现有匿名版行为不变。

### Swift 侧已具备的对接点

- 说话人映射已有完整读写：`speakerLabels`、`updateSpeakerLabel(...)`、
  `loadSpeakerMap(for:)`、`detectedSpeakers`。
- `regenerateReport` 的进程调用骨架已就绪，只需扩展参数。

---

### 实现情况（0.2.9）

- `scripts/regenerate_session.py` 新增 `--speaker-map-file`，把真实姓名合并进说话人
  映射并按实名版重生成；同时修复原第 142 行 `if a, b:` 语法错误，并在原导出格式
  组合为空时回退。
- `MeetingLibraryStore.regenerateReport` 通过 `writeSpeakerOverridesFile` 把已标注的
  说话人姓名写入临时 JSON 后传入，进程结束即清理临时文件。
- 详情页「更改纪要类型」确认弹窗会根据是否已标注姓名，提示将生成实名版或引导先填写姓名。
