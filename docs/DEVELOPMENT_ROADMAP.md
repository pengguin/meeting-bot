# 会议纪要助手开发路线图

更新时间：2026-07-31

## 路线图原则

- 当前阶段先解决技术底座问题；底座验收完成前，不并行开发会议库增强、批处理、模型管理等新增功能。
- 版本号采用语义化节奏：日常修补推进 `0.0.1`，中等版本推进 `0.1`，大版本推进 `1`；中等和大版本只在明确确认后推进。
- 每个版本必须同时交付代码、自动化测试、App 构建、安装/升级验证、更新记录、使用说明和线程交接文档。
- 会议录音、转录稿、纪要、密钥和运行状态默认只保存在本机；新增网络能力不得改变这一隐私边界，除非用户明确启用并看到提示。
- 数据格式、任务状态、安装升级和删除操作必须失败关闭，并具备预检、原子写入、可恢复备份、回滚和可读错误。
- 不以单次编译或单元测试通过作为交付依据；底座修改必须验证真实 App 启动、代表性会议任务和安装/升级路径。

## 执行顺序与冻结规则

后续开发严格按照以下顺序推进：

1. 收口当前安全与安装修复，建立可信基线。
2. 完成数据完整性、配置和模块边界治理。
3. 统一任务账本、状态机和重启恢复。
4. 隔离模型进程，建立资源限制、超时和可观测性。
5. 完成安装、升级、回滚、诊断和发布工程。
6. 通过底座总验收后，再从功能池选择新增功能。

除修复阻断问题外，前一阶段未通过验收时不得启动后一阶段。新增功能不得自行实现另一套任务状态、数据存储、日志或依赖检测机制。

## 已完成基线

### 0.5.0 架构与发布完整性

- 飞书 I/O、音频流水线、运行状态从 `bot.py` 拆分为独立模块。
- 飞书消息流、音频处理、状态持久化和载荷篡改检测纳入自动化测试。
- 会议库使用后台 actor 扫描，并以会话目录指纹建立内存增量索引。
- 安装载荷在覆盖旧版前校验逐文件 SHA-256；安装盘生成机器可读发布清单。
- 发布清单预留 ECDSA P-256/SHA-256 签名入口。

### 0.5.1 后台服务稳定性

- 修复模块拆分后后台启动入口仍引用旧函数名造成的 LaunchAgent 重启循环。
- 服务停止时，界面以 LaunchAgent 实际状态覆盖陈旧运行状态文本。
- 增加启动入口回归测试。

## 当前收口：安全修复候选基线

目标：先完整验证并收口当前工作区中的安全、安装识别和资源边界修复，不在该批修改中继续加入产品功能。

- 完成飞书会话隔离、文件访问边界、会话元数据保护和 LLM 执行隔离修复。
- 完成封闭式安装载荷清单、Swift 预执行验证、签名失败关闭和卸载目录边界修复。
- 依赖检测不得假定通过 Homebrew 安装；应识别系统 `PATH`、常见直接安装位置以及 npm/npx 等受支持入口，并显示实际命令位置和验证结果。
- 核对所有外部输入的大小、数量、路径、超时、并发和输出上限。
- 将安全修复新增测试、实际测试数量、版本、构建号和文档统一后再提交。

验收：全量 Python 测试通过；Swift App 无警告编译；开发版 App 可正常启动并完成一条代表性会议任务；全新安装、已有环境复用、升级和卸载边界验证通过；工作区变更按单一修复主题提交。

## 0.6 技术底座一：数据与模块边界（已完成）

目标：确保任何解析失败、路径配置错误或中途退出都不会破坏用户数据，并把后续任务内核建立在稳定接口上。

- 为会议元数据、任务状态、配置和缓存建立明确的数据版本与迁移入口。
- 读取或解码失败时保留原文件，隔离损坏副本并给出恢复入口；禁止以内存空对象覆盖未知或损坏数据。
- 统一原子写入、文件锁、备份保留、目录所有权和路径白名单规则；移动、迁移、卸载只处理应用明确拥有的文件。
- 统一配置读取、钥匙串访问、环境变量兼容和敏感信息脱敏规则，消除 Python、Swift 和安装脚本之间的分叉判断。
- 明确飞书 I/O、任务编排、音频处理、纪要生成、导出和持久化之间的接口；按这些边界继续拆分超大文件，避免仅为缩短文件而重构。
- 为数据迁移、损坏恢复、并发写入、异常中断、目录迁移和卸载边界增加测试。

验收：构造损坏元数据不会造成二次覆盖；迁移可重复执行且失败可回滚；自定义目录中的无关文件不会被移动或删除；核心模块不通过隐式全局状态共享任务或密钥。

完成结果：共享持久化层已覆盖会议来源元数据、草稿、检查点、运行状态和关键会议产物；Python 数据文件及 Swift 会议库元数据具备版本、写前备份和损坏写保护；恢复工具只允许在显式根目录内扫描、隔离和恢复。104 项自动化测试及开发版 App 构建通过，版本 `0.6.0`、构建号 `35`。

## 0.7 技术底座二：统一任务内核

目标：本地新增会议和飞书任务使用同一套持久化任务账本、状态机和恢复规则。

- 建立统一任务 ID、来源、幂等键、优先级、阶段、检查点、重试次数、错误分类和产物引用模型。
- 明确定义排队、运行、暂停、取消、失败、等待用户处理、可重试和完成之间的合法转换。
- 本地 App 与飞书入口只负责提交任务，不再分别维护独立的执行事实来源。
- 服务崩溃、App 退出或系统重启后自动审计未完成任务，区分可续跑、需重试和需用户处理。
- 同一材料、重复飞书事件和重复按钮操作必须通过幂等键收敛，不产生并行重复任务。
- 为账本锁、进程重启、并发上限、重复消息、暂停继续和阶段产物复用增加进程级集成测试。

验收：任务状态只有一个权威来源；重启前后状态一致；暂停和取消不会删除可复用产物；同一输入不会重复转写或生成两份正式会议；进程级恢复测试稳定通过。

## 0.8 技术底座三：进程隔离、资源治理与可观测性

目标：模型或外部工具异常不会拖垮主服务，长录音的资源消耗和卡顿原因可定位、可限制、可恢复。

- 将 ASR、说话人分离和其他高风险计算移入可独立终止和重启的 worker 进程。
- 对进程组、临时文件、子进程继承环境和退出清理建立统一规则，暂停或超时后不得遗留后台计算。
- 按 CPU、内存、模型类型和磁盘余量设置并发及资源预算；达到限制时进入可解释的等待状态，而不是抢占后崩溃。
- 为下载、预处理、说话人分离、转写、LLM 和导出分别设置软超时、硬超时、重试和熔断策略。
- 建立结构化本地日志、阶段耗时、峰值内存、失败分类和关联任务 ID；默认不记录会议正文、Token 或密钥。
- 增加脱敏诊断包和一键清理入口，能够判断服务状态、任务状态、模型状态和依赖位置是否一致。
- 建立短音频、长音频、并发任务、低磁盘、低内存、模型异常和强制退出压力测试。

验收：worker 崩溃不会结束主服务；暂停、取消和超时后无遗留模型进程；资源上限可配置且压力测试可重复；诊断包通过敏感信息扫描并足以定位阶段性故障。

## 0.9 技术底座四：安装、升级与发布工程

目标：不同安装来源和既有环境下都能得到可预测结果，失败不破坏当前可用版本。

- 将安装流程明确拆为环境发现、兼容性判断、计划预览、执行、验证和回滚，界面显示当前步骤和可操作的错误原因。
- 依赖识别以可执行文件验证和版本能力为准，不以 Homebrew、npm、curl 等安装方式作为唯一判断条件。
- 安装和升级不得静默替换用户自定义目录、现有 Python 环境或外部工具；复用、并存、迁移和重新安装必须清楚说明。
- 建立稳定更新源，使用签名发布清单、安装包哈希和 macOS 代码签名共同验证更新；支持跳过版本、下载进度、失败重试和自动回滚。
- 冻结数据迁移协议，验证跨版本升级、降级阻止、备份恢复和卸载后保留用户资料。
- 完成键盘操作、VoiceOver、动态字体、深浅模式、高对比度和错误引导检查。
- 建立全新安装、非 Homebrew 依赖、离线安装、跨版本升级、磁盘不足、网络中断、权限不足和损坏安装包回归矩阵。

验收：支持的依赖安装方式均能正确发现或给出准确引导；更新失败可自动恢复旧版本；关键流程可仅用键盘完成；发布产物、版本元数据和文档一致；回归矩阵可重复执行。

## 底座总验收门槛

以下条件全部满足后，才允许进入新增功能开发：

- 没有未处理的高严重性安全问题，现有安全修复已提交并通过回归验证。
- 用户数据具备版本、迁移、原子写入、损坏恢复和备份策略。
- 本地与飞书任务使用统一持久化账本，重启、暂停、取消和重试行为一致。
- 模型计算已与主服务隔离，资源、超时和子进程生命周期受控。
- 安装、升级和卸载对自定义目录及外部工具失败关闭，并具备回滚。
- 全量单元测试、进程级集成测试、App 构建、代表性真实任务和安装矩阵全部通过。
- 文档、版本、构建号、发布清单和实际 App 内容一致。

## 后置功能池

底座通过总验收后，再根据用户价值和实现风险选择版本，不预先并行开发：

- 持久化会议库索引，支持标题、正文、说话人、标签、备注和日期组合检索。
- 批量导入录音/转录稿、批量打标签、移动文件夹和重新导出。
- 重复会议检测、合并提示以及可撤销的批量整理。
- 飞书可更新进度卡片和更细的任务通知控制。
- 模型下载、校验、版本、磁盘占用、清理和设备基准测试界面。
- “准确率优先 / 平衡 / 速度优先”预设，以及音频预处理和说话人嵌入缓存。
- 会议库高级筛选、保存视图、导出模板和其他界面增强。

任何功能进入开发前，必须明确复用统一任务账本、数据迁移、日志、资源预算和安装检测接口，不得绕过底座另建临时实现。

## 1.0 稳定分发

目标：在技术底座和首批经确认功能稳定后，形成可长期维护、可验证安装、可安全升级的稳定版。

- 使用 Apple Developer ID 对 App 和安装盘签名并完成 Apple 公证与 stapling。
- 正式发布 ECDSA P-256 公钥；在线更新必须同时通过发布清单签名、安装包哈希和 macOS 代码签名校验。
- 提供支持周期、兼容矩阵、备份恢复与卸载说明。
- 关键业务路径具备单元、进程级集成、安装升级和端到端测试；严重错误必须阻止发布。
- 完成隐私说明、安全审计、第三方依赖清单和许可证归档。

验收：全新 Mac 可按文档完成安装；Gatekeeper 无额外绕过操作；升级可回滚；发布产物、版本元数据和文档一致；没有未处理的高严重性安全问题。

## 外部发布条件

Developer ID 签名和 Apple 公证依赖有效的 Apple Developer 账号、证书、Team ID 与公证凭据，不能在仓库中伪造或提交。代码侧只提供签名、校验和失败关闭能力；取得正式凭据后，应在受保护的发布环境中完成签名、公证、stapling 和 Gatekeeper 验证，再把对应版本标记为可公开分发。
