# 会议纪要助手开发路线图

更新时间：2026-07-16

## 路线图原则

- 版本号采用语义化节奏：日常修补推进 `0.0.1`，中等版本推进 `0.1`，大版本推进 `1`；中等和大版本只在明确确认后推进。
- 每个版本必须同时交付代码、自动化测试、App 构建、安装/升级验证、更新记录、使用说明和线程交接文档。
- 会议录音、转录稿、纪要、密钥和运行状态默认只保存在本机；新增网络能力不得改变这一隐私边界，除非用户明确启用并看到提示。
- 先保证任务可恢复和数据不丢失，再优化速度和视觉效果；涉及迁移、覆盖和删除的操作必须具备预检、回滚和可读错误。

## 0.5.0 架构与发布完整性（已完成）

目标：降低核心模块耦合，避免超大会议库阻塞界面，并为后续在线更新建立可验证的发布元数据。

- 飞书 I/O、音频流水线、运行状态从 `bot.py` 拆分为独立模块。
- 飞书消息流、音频处理、状态持久化和载荷篡改检测纳入自动化测试。
- 会议库使用后台 actor 扫描，并以会话目录指纹建立内存增量索引。
- 安装载荷在覆盖旧版前校验逐文件 SHA-256；安装盘生成机器可读发布清单。
- 发布清单预留 ECDSA P-256/SHA-256 签名入口；没有真实密钥时明确标记为未签名。

验收：57 项测试通过；App 编译无警告；无签名和 ECDSA 签名载荷验证通过，文件或清单篡改验证失败；App 版本 `0.5.0`、构建号 `32`。

### 0.5.1 稳定性修补（已完成）

- 修复模块拆分后后台启动入口仍引用旧函数名造成的 LaunchAgent 重启循环。
- 服务停止时，界面以 LaunchAgent 实际状态覆盖陈旧运行状态文本。
- 增加启动入口回归测试；版本 `0.5.1`、构建号 `33`。

## 0.6 统一任务调度与恢复

目标：把本地新增会议和飞书任务统一到同一套持久化任务账本，解决并发、重启恢复和资源竞争。

- 建立统一任务 ID、来源、优先级、阶段、检查点、重试次数和错误分类模型。
- App 提供任务队列视图，可暂停、继续、取消和调整待处理顺序。
- 按 CPU、内存和模型类型限制并发；说话人分离、ASR、LLM 和导出分别设置资源预算。
- 后台服务崩溃或系统重启后自动审计未完成任务，区分可续跑、需重试和需用户处理。
- 为任务账本、重启恢复、并发上限和重复消息增加进程级集成测试。

验收：同一份材料不会生成重复任务；重启后任务状态一致；暂停不会删除阶段产物；资源上限可配置且有压力测试结果。

## 0.7 会议库检索与批量工作流

目标：让会议库在大量会话下仍可快速检索，并减少重复整理操作。

- 将内存增量索引升级为持久化索引，支持标题、正文、说话人、标签、备注和日期组合检索。
- 支持批量导入录音/转录稿、批量打标签、移动文件夹和重新导出。
- 增加重复会议检测和合并提示，不自动删除原始材料。
- 为飞书消息增加可更新的进度卡片，避免用多条文本消息刷屏。
- 增加索引重建、自检和损坏恢复入口。

验收：万级会议元数据扫描不阻塞主线程；检索结果可解释；批量操作可撤销或在执行前确认；索引删除后可从会话目录完整重建。

## 0.8 模型与性能管理

目标：降低长录音处理时间、峰值内存和模型故障对主服务的影响。

- 将 ASR 和说话人分离移入可重启 worker 进程，隔离模型崩溃与内存泄漏。
- 增加模型下载、校验、版本、磁盘占用和清理界面。
- 按设备基准测试推荐模型、量化方式、批量大小和线程数，保留“准确率优先 / 平衡 / 速度优先”预设。
- 缓存可复用的音频预处理和说话人嵌入，明确缓存失效规则。
- 记录阶段耗时、峰值内存和失败类型，仅保存在本机并可一键清除。

验收：worker 异常不会结束主服务；模型文件有来源和哈希校验；性能预设可回退；资源指标不会包含会议正文或密钥。

## 0.9 发布候选与可维护性

目标：把开发者可用版本收敛为可面向普通用户测试的发布候选版。

- 建立稳定更新源，使用已签名发布清单校验版本元数据和安装包。
- 提供可选择更新、跳过版本、下载进度、失败重试和自动回滚。
- 增加脱敏诊断包，默认排除录音、转录、纪要、Token 和 API Key。
- 完成键盘操作、VoiceOver、动态字体、深浅模式和高对比度检查。
- 建立全新安装、跨版本升级、离线安装、磁盘不足、网络中断和权限不足的回归矩阵。

验收：更新失败不影响当前版本；诊断包通过敏感信息扫描；关键流程可仅用键盘完成；回归矩阵可重复执行。

## 1.0 稳定分发

目标：形成可长期维护、可验证安装、可安全升级的稳定版。

- 使用 Apple Developer ID 对 App 和安装盘签名并完成 Apple 公证与 stapling。
- 正式发布 ECDSA P-256 公钥，在线更新必须同时通过发布清单签名、安装包哈希和 macOS 代码签名校验。
- 冻结数据格式和迁移策略，提供支持周期、兼容矩阵、备份恢复与卸载说明。
- 关键业务路径具备单元、集成、安装升级和端到端测试；严重错误必须阻止发布。
- 完成隐私说明、安全审计、第三方依赖清单和许可证归档。

验收：全新 Mac 可按文档完成安装；Gatekeeper 无额外绕过操作；升级可回滚；发布产物、版本元数据和文档一致；没有未处理的高严重性安全问题。

## 发布门槛

Developer ID 签名和 Apple 公证依赖有效的 Apple Developer 账号、证书、Team ID 与公证凭据，不能在仓库中伪造或提交。代码侧已保留签名清单和发布校验入口；取得正式凭据后，应在受保护的发布环境中完成签名、公证、stapling 和 Gatekeeper 验证，再把对应版本标记为可公开分发。
